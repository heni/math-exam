# Сборка материалов

## Цепочка

```
theory.md   --pandoc--> LaTeX --xelatex--> theory.pdf     (scrartcl, amsthm)
slides.md   --pandoc--> beamer(metropolis) --xelatex--> slides.pdf
examples.py --jupytext --execute--> examples.ipynb
```

Markdown с TeX-вставками — основной формат: теоремные окружения пишутся прямо
как `\begin{theorem}...\end{theorem}` и проходят через pandoc в LaTeX без
изменений, а проза, списки и таблицы остаются читаемыми в исходнике.

## Команды

```bash
make                  # всё, что имеет исходники
make -j4              # то же параллельно
make q11              # все артефакты вопроса 11
make new Q=11         # развернуть шаблоны в каталоге вопроса 11
make theory           # только конспекты
make slides           # только презентации
make notebooks        # только ноутбуки (с исполнением)
make check            # проверки согласованности
make list             # таблица готовности по 20 вопросам
make clean            # удалить собранные артефакты
```

**pandoc запускается из корня проекта.** Настройки в `build/*.yaml` ссылаются
на `build/preamble-*.tex` относительно корня; каталог вопроса добавляется в
`--resource-path` целью Makefile. Поэтому картинки в `theory.md`/`slides.md`
пишутся как `figures/fig-01.pdf` — относительно каталога вопроса, а не корня.

## Окружение Python

Пакеты ставятся в локальный `.venv`; Makefile берёт интерпретатор оттуда, если
каталог есть, и системный, если нет. Установка с нуля:

```bash
make venv      # python -m venv .venv + requirements.txt + регистрация kernel'а
make freeze    # зафиксировать фактические версии в requirements-lock.txt
```

**Регистрация kernel'а обязательна.** Без неё `jupytext --execute` падает с
`No kernel found that matches the current python executable` — ещё до запуска
ячеек. `make venv` делает это сам; вручную:

```bash
.venv/bin/python -m ipykernel install --user --name math-exam
```

## Проверка сборки

Собранный PDF — не доказательство корректности набора: зелёная сборка LaTeX не
значит, что строка не печатается за полосу. Для нестандартного набора (широкие
формулы, `array`, таблицы во всю ширину слайда) геометрию мерить:

```bash
pdftotext -bbox questions/11-chebyshev-polynomials/slides.pdf - | grep -c 'xMax="4[6-9][0-9]'
```

Проще — глазами по собранному PDF, но именно по собранному, а не по исходнику.

## Шрифты и Cyrillic

`lang: ru` + `polyglossia` + xelatex: русский набор, переносы, русские имена
окружений (`Теорема`, `Доказательство` — заданы в преамбулах). В beamer русские
имена теоремных окружений заданы через `\deftranslation`, потому что metropolis
берёт их из beamer-словаря, а не из `amsthm`.

Если менять шрифт — менять в `build/defaults-*.yaml`, и проверять, что в нём
есть кириллица и математические начертания курсивом.

## Ноутбуки

Источник в git — `examples.py` в формате jupytext percent (`# %%` разделяет
ячейки, `# %% [markdown]` — текстовые). Ноутбук `examples.ipynb` —
**производный, но тоже коммитится**: это один из трёх обязательных артефактов
вопроса, и его смотрят с выводами и картинками, а не запускают.

Отсюда правило: правка идёт **в `.py`**, затем `make notebooks`. Правка прямо
в `.ipynb` теряется при следующей сборке. Сборка исполняет ноутбук, и падение
ячейки роняет `make` — это гейт: невоспроизводимый пример не попадает в
материалы. Проверено подстановкой падающей ячейки: `make` завершается с кодом 2,
а прежний валидный `.ipynb` не перезаписывается (остаётся старше своего `.py`,
и `make check` это показывает).

## Разметка формул: пять ловушек

**Выключная формула в прозе пишется `$$…$$`, а не `\[…\]`.** Для pandoc-markdown
обратная косая перед пунктуацией — это экранирование, поэтому `\[` превращается
в обычную скобку `[`, формула попадает в LaTeX как текст и сборка падает на
первом же `\begin{aligned}`. Внутри блоков `\begin{theorem}…\end{theorem}` этого
не происходит: содержимое таких окружений pandoc пропускает как сырой LaTeX, и
`\[…\]` там работает. Отсюда практическое правило: `\[…\]` — только внутри
теоремных окружений, `$$…$$` — везде ещё.

**В подписях matplotlib работает mathtext, а не LaTeX.** Он не знает `\ge`,
`\le`, `\neq` — нужны `\geq`, `\leq`, `\ne`. Ошибка вылезает не при разборе
строки, а при отрисовке, то есть на `savefig`, и роняет сборку ноутбука.

**Markdown-разметка внутри теоремных окружений не работает.** Содержимое
`\begin{theorem}…\end{theorem}` pandoc отдаёт в LaTeX как есть, поэтому
`**жирный**` печатается со звёздочками, а `*курсив*` — со звёздочкой. Внутри
окружений писать `\textbf{…}` и `\emph{…}`. Это **тихая** ловушка, в отличие от
двух предыдущих: сборка проходит, и дефект виден только в собранном PDF. Проверка
— `pdftotext theory.pdf - | grep -c '\*\*'`, должно быть 0.

**Одиночная обратная косая в конце строки внутри окружения ломает разбор.**
Содержимое `\begin{...}...\end{...}` pandoc читает как сырой LaTeX, и `\` перед
переводом строки сбивает ему токенизацию: окружение попадает в `.tex` дважды —
один раз верно, второй раз искажённым огрызком, — после чего сборка падает с
«Missing $ inserted» и номером строки в **сгенерированном** файле, которой в
исходнике нет. Перевод строки `\\` безвреден; вне окружений (в прозе и в
`$$`-блоках) одиночная `\` безвредна тоже. Ловится `tools/check.sh`, пункт 10.

**Кириллица внутри `\mathrm` печатается в конспекте и пропадает в презентации.**
Индекс вида `N_{\mathrm{ЦПТ}}` собирается без ошибки в обоих артефактах, но
beamer с темой metropolis берёт математический шрифт из Latin Modern, где
кириллицы нет, и буквы просто не выводятся. Сборка при этом успешна, и дефект
виден только предупреждением «Missing character» в логе. Писать `\text{...}`:
он берёт текстовый шрифт. Ловится `tools/check.sh`, пункт 11.

Три ловушки из пяти шумные: сборка останавливается с внятным сообщением. Опасен
соблазн «поправить на глаз» в уже собранном PDF — исходник при этом останется
сломанным. Две тихие (markdown внутри окружений и кириллица в `\mathrm`) видны
только в собранном PDF или в логе, и обе закрыты гейтами.

## Вёрстка конспекта: одна колонка, 10 pt

Конспект набирается **одной** колонкой кеглем 10 pt с полями 20 мм. Две колонки
пробовались и отвергнуты по измерению, а не по вкусу: при ширине колонки около
247 pt выкладки вопроса 11 печатаются за полосу — измерено `pdftotext -bbox`,
десятки слов с `xMax` до 604 pt при ширине страницы 595 pt. Причина в жанре:
у нас длинные выкладки с дробями и индексами, которые не переносятся.

Что даёт компактность без ущерба: кегль 10 pt вместо 11, поля 20 мм вместо 25,
`linestretch: 1.0`. На вопросе 11 это 17 страниц вместо 22.

Широкая таблица в одноколоночной вёрстке набирается сырым LaTeX
(`\begin{center}\small\begin{tabular}…`), а не markdown-таблицей: pandoc
превращает markdown-таблицы в `longtable`, а он несовместим с `twocolumn` —
если к двум колонкам когда-нибудь вернутся, таблицы уже не помешают.
